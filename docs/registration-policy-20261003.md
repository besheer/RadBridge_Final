# Registration fields, doctor selection and visit grouping

Field Rules (/admin/field-rules) controls the existing patient name, phone, national ID, nationality, email and address rules. Calendar registration, calendar booking, legacy registration and OCR-assisted patient creation use the same server validator. Existing patient selection checks the saved demographics. Calendar inputs reflect visibility, requiredness and lengths. Core identity, DOB/age parsing, branch/device compatibility and procedure readiness gates remain authoritative. Conflicting required-but-hidden rules and invalid length ranges are rejected; rule changes are audited.

Registration has AUTO or MANUAL doctor selection. Only assignment.manage may choose a doctor. Manual selection validates an active reporting doctor, all visit modalities, branch and whole-visit capacity; normal assignment service enforces special-doctor eligibility when orders are assigned. The manual reservation survives booking/check-in, assigns all registered examinations atomically and is excluded from automatic offers, direct automatic assignment and deadline withdrawal. Other booking staff may carry an existing reservation forward without choosing a different doctor.

Multiple examinations created in one submission share a visit automatically. To add examinations on a different device, choose Existing Patient, the same date/branch, Multiple Examinations and the explicit visit. Patient ID alone never implies a visit. A visit can remain registration-open while more exams are expected, blocking automatic assignment. Unconverted active bookings also block automatic assignment. Existing offers are invalidated after membership changes. Started reading, saved reports, locked/final work or existing automatic assignments prevent registration-time membership changes.

Close registration on the final addition, or through the Complete Visit Registration action on Link Visits. Closing a visit attempts the normal offer workflow; eligibility and all-examination readiness are still required. Manual visit ownership remains manual. The reporting doctor is distinct from the referring doctor.

Schema changes are two additive assignment_visit columns. Deployment preserves the existing RIS configuration and port. Rollback restores the previous image and disables no existing assignment timer; the added columns are backward-compatible and can remain. Do not remove clinical data or final report files during rollback.
