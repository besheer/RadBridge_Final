## كيف نستخدمه؟

1. نحدد الجزء المطلوب تطويره ونقرأ ملفات الكود المرتبطة به.
2. نحول التغيير إلى نطاق واضح ومعايير قبول، بدل تغيير المشروع كله مرة واحدة.
3. نثبت خط الأساس في بيئة اختبار مستقلة، وننفذ خطة الاختبار.
4. نراجع النتيجة ثم نقرر النشر وفق الصلاحية وخطة الرجوع.

## تصنيف المعلومات

- **Current source:** بنية أو وظيفة ظاهرة في الكود، وليست شهادة بنجاح كل تكامل خارجي.
- **Recorded release evidence:** نتيجة اختبار أو تحقق مسجلة للـcheckpoint المحدد.
- **Proposed:** تنظيم أو تغيير مستقبلي لم ينفّذ بعد.
- **Deferred:** متطلب مؤجل أو خارج هذه المرحلة.

هذه الملفات لا تعدل الكود التنفيذي أو قواعد البيانات أو إعدادات الإنتاج. مشروع بوابة DICOM المستقلة للفروع خارج نطاق هذا المخطط. لا يحتوي المخطط على أسرار أو بيانات مرضى.
