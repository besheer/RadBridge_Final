# ADR-001: preserve behavior while introducing a pure domain boundary

Status: proposed for review in the development-foundation PR, 2026-10-10.

Context: the source snapshot has a large Flask entry point and already extracted policy modules, historical deployment definitions and conservative binary omissions. A big-bang rewrite would obscure clinical regressions and invalidate the recovery baseline.

Decision: use a monolith with explicit pure domain modules. Start with readiness, keep a compatibility facade, add behavior contracts and isolate synthetic execution/configuration. Do not change readiness thresholds, matching identity, report state, routes or schema during extraction.

Consequences: old imports remain valid; new code can depend on the domain without Flask/SQLAlchemy. Database/PACS/editor adapters and orchestration remain outside domain. Broader extraction, asset restoration, full integration stack and clinical UAT require separate stages. CI must expose real failures rather than silently skip missing requirements.

Environment: user explicitly authorized working on GitHub independently of the live host. Historical R8-only paths in root AGENTS.md are not used for this isolated development task. This does not authorize any live/stage deployment; no production resource is changed.
