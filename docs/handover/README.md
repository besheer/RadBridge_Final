## Handover boundaries

- This documentation was generated by inspecting the reviewed source and the recorded release evidence. It does not constitute a new clinical acceptance test or a fresh full restore rehearsal.
- A screen, file name, declared route or ORM model is not proof that an external integration works. Validate its worker, configuration, credentials, audit trail and external acknowledgement.
- Patient identity matching, locked/final reports, financial settlements and role/branch boundaries require explicit tests before changes.
- The proposed independent branch DICOM gateway is a separate project. Do not turn its requirements into production RadBridge behavior without a new implementation scope.
- Credentials, patient examples, real DICOM files, database dumps and private environment values are intentionally absent.

## First session for the next maintainer

Confirm the baseline commit and working tree; inspect current service health, DB dialect and mounts without printing secrets. Reconcile manifest exclusions with assets needed for the task. Run tests only in an isolated synthetic environment. Select one issue from the backlog, document its acceptance conditions, make the smallest coherent change, validate roles and direct URLs, and perform a controlled release with a rollback point if deployment is authorized.
