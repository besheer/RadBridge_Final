# Physician VERIFIED / FINAL counts and case list — 8 October 2026

GET `/coordinator/physician-reports` displays current VERIFIED and FINAL report counts by reporting physician/branch, with a matching paginated case report list. It is available in the Finance menu to active `reports.coordinate` or `finance.doctor_share.view` users. Non-wildcard users must have a branch and may only query that branch. Physician filter choices come from that permitted dated workload, including historical inactive physicians. Viewing the list does not grant report editing or case-view permission; case links appear only with existing `orders.view` permission.

Filters: inclusive start/end dates, branch, physician, and ALL/VERIFIED/FINAL status. VERIFIED original reports use Report.verified_at and may live on REPORTING orders, as required by the existing writer. Original FINAL reports require both Report and Order FINAL and use Report.finalized_at. This is a current-state workload report, not a history of every verification event: an original case already FINAL appears only under FINAL. Missing lifecycle dates never fall back to appointments or updated_at. Records without the date required by their current status do not enter a dated period. Original attribution is Order.assigned_doctor_id, not the approver name or financial performing physician.

ReportRevision VERIFIED/FINAL rows use their own dates and doctor_id, and are shown separately as ADDENDUM/REPLACEMENT with revision number. Multiple corrections can refer to one case; summary includes distinct corrected cases and separate counts of VERIFIED/FINAL corrections. Neither revision versions nor original report versions enter the query, so version retries do not multiply counts. Corrections do not increase original case counts or book financial entitlements.

Each list row shows accession, patient name, physician, branch, modality/procedure, original or correction type, current report status and its status date. Summaries aggregate the entire filtered result; list pagination is 50 rows per page with stable date/order/type/report-ID sorting. Paging retains the chosen filters and does not change totals. Negative, malformed or out-of-range pages and invalid statuses/dates/IDs are rejected. Empty and unassigned records are explicit. SQL performs aggregation and pagination rather than loading all cases into Python.

Module: `physician_report_workload.py`; template: `templates/physician_report_workload.html`; route registration in `app.py`; navigation in `templates/base.html`. No schema change, writes, report content changes or cash/settlement operations are introduced. The existing FINAL-only report and its URL remain available.
