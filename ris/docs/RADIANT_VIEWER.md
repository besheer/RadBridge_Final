# RadiAnt third viewer

Adds RADIANT beside OHIF/WEASIS, including per-doctor default preference. Existing OHIF and Weasis paths remain compatible. No database migration is needed; preferences use the existing profile JSON.

RadiAnt is a Windows desktop viewer. Its documented command line opens local ZIP archives, not a hosted ZIP URL. RadBridge supplies a per-user Windows launcher (client_tools/RadiAntBridge), registered as radbridge-radiant://, which downloads an authorized ZIP and invokes the installed RadiAntViewer.exe. RadiAnt installation and licensing are separate.

The signed native-download capability uses its own purpose/salt, expires after 1200 seconds, binds issuing user/order/study/UID/patient ID/DOB and rechecks current case permissions, clinical scope, branch, assignment, activity and demographic reconciliation. Original DICOM headers in every ZIP member are validated before delivery; current authorization is rechecked after preparation. No unrestricted PACS endpoint is exposed and no identity is corrected automatically. Delivery uses no-store/no-referrer headers; Gunicorn access token paths are redacted. The launcher allows only the configured HTTPS origin and exact archive path, refuses redirects, bounds archives to 1 GiB and verifies SHA-256 before invoking RadiAnt. Existing validation caps archive expansion at 4 GiB and 20000 entries. Larger studies require a separate scalable transport design.

Public RIS configuration must be an HTTPS origin. GET /doctor/viewers/radiant/setup.zip requires doctor workspace and reports.view. GET /radiant-images/{order_id}/{capability}/study.zip requires the signed capability; browser cookies alone do not grant access. Case-viewer launch and image preparation are audited without recording the bearer token. A downloaded clinical copy remains on the workstation after capability expiry; workstation retention must manage it.
